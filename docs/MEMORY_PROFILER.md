# Профиль памяти Rust

Реализован локальный диагностический профиль стеков с flame graph: выделенные байты, количество выделений, оставшиеся живые байты и блоки. Это не сервер Pyroscope и не интеграция с Grafana.

## Подключение

Включите feature `memory` у зависимости `rbench` и оберните существующий глобальный аллокатор:

```rust
use rbench::memory::{self, Allocator};
#[global_allocator]
static ALLOC: Allocator<std::alloc::System> = Allocator(std::alloc::System);
fn main() -> rbench::Result<()> {
    memory::profile(|| {
        // Сценарий приложения. Завершите рабочие потоки до выхода отсюда.
    })?;
    Ok(())
}
```

Для профилирования существующего `TrackingAllocator` можно обернуть его в `memory::Allocator`; второй `#[global_allocator]` устанавливать нельзя. Без переменной, которую передаёт runner, `memory::profile` просто исполняет сценарий.

```sh
cargo build --release --example memory --features memory --offline
cargo rbench run --memory --program target/release/examples/memory -o .rbench/memory-demo
cargo rbench serve .rbench/memory-demo
```

`--memory` запускает один диагностический процесс; baseline/варианты в том же запуске запрещены. Обычные сравнения отчётов исключают такой запуск. Во время работы доступен стандартный live UI; после завершения появляется кнопка «Память». Для CI: `--no-ui`.

Сохраняются `memory.json`, автономный `memory.html`, обычный `run.json` и отчёты. SHA-256 профиля записывается в provenance запуска. Worker без инструментации завершит запуск с ошибкой отсутствующего профиля. Поиск фильтрует стеки; нажатие на блок flame graph приближает ветку; таблица показывает 100 крупнейших полных стеков, JSON сохраняет все записанные группы.

## Охват и ограничения

- Профиль видит только обращения через установленный Rust allocator в выбранном интервале. RSS, GPU, драйверы, mmap и native-библиотеки сюда не входят.
- Одна сессия на процесс, буфер 8192 событий, глубина стека до 24 кадров. Переполнение или конкуренция отмечаются как потерянные события; такой профиль неполный, его остатки и пик нельзя считать точными.
- Realloc учитывается как замена блока: в поток выделений входит весь новый размер, а не только прирост. Неудачный realloc не удаляет прежний блок.
- Профайлер исключает собственные вложенные аллокации. Символизация выполняется после остановки сбора. Для имён файлов и строк собирайте worker с debug information; без символов возможны адреса вместо имён.
- Память, выделенная до сессии, не входит в остаток. Блок, живой в конце сессии, не обязательно является утечкой. Типы объектов и граф владения не восстанавливаются.
- Сбор стеков заметно влияет на время выполнения. Используйте отдельный обычный запуск для сравнения скорости.
- При аварийном завершении до сохранения профиль может отсутствовать; runner не подменяет это нулевой памятью.

Для Forma следующий этап интеграции — обернуть её аллокатор и отмечать границы диагностического сценария. В текущем изменении подключён проверочный Rust worker; полноценные профили Forma ещё не получены.
